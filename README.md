# 🌱 星芽 StarSprout —— 跨平台心理健康与学习陪伴系统

> *"不必成为太阳，做一颗发芽的星星就好。"*

## 一、用户心理画像与行为偏好分析

### 1.1 核心心理困境矩阵

| 维度 | 现状描述 | 深层心理动因 | 行为表现 |
|------|----------|--------------|----------|
| **自我效能感** | 极低——放弃编程，畏惧数学 | 习得性无助：多次失败后内化"我不行"的信念 | 回避挑战，不敢开始 |
| **情绪调节** | 抑郁+焦虑共病 | 前额叶执行控制减弱，杏仁核过度激活 | 情绪波动大，易崩溃 |
| **归属感** | 对学校环境抗拒，周末返家 | 安全感锚点仅在家，学校=威胁情境 | 空间逃避，社交退缩 |
| **自我同一性** | 缺乏目标、自信与爱好 | 同一性弥散——未经历探索-承诺过程 | 迷茫，不知"我是谁""要去哪" |
| **认知负荷** | 高数+线代双重压力 | 工作记忆被焦虑侵占，推理资源不足 | 学不进、记不住、想不通 |
| **动机系统** | 外在压力驱动，内在动机枯竭 | 自主需求、胜任需求、关系需求三重匮乏 | 拖延、敷衍、放弃 |

### 1.2 行为偏好推断

```
┌──────────────────────────────────────────────────────┐
│  偏好维度          │  回避 ←──────────→ 趋近          │
├──────────────────────────────────────────────────────┤
│  学习场景          │  教室/图书馆    →  家/咖啡馆     │
│  学习节奏          │  固定课表      →  弹性自主       │
│  反馈方式          │  分数/排名     →  可视化/叙事     │
│  内容粒度          │  长篇讲义      →  微单元(3-5min) │
│  交互复杂度        │  多步操作      →  单次点击       │
│  社交模式          │  面对面        →  匿名/异步       │
│  错误处理          │  扣分/批评     →  无评判探索     │
│  目标设定          │  长期宏大      →  每日微目标     │
│  美学偏好          │  冷峻学术      →  温暖自然       │
└──────────────────────────────────────────────────────┘
```

### 1.3 设计原则推导

1. **脚手架而非教授（Scaffolding）**：提供恰到好处的支持，随能力增长逐步撤离
2. **成功螺旋（Success Spiral）**：确保每次交互都在用户最近发展区内，积累"我能行"的微小证据
3. **情绪先行（Emotion First）**：每次打开先问候情绪，再引导任务——情绪不好时不强推学习
4. **柔性边界（Soft Boundaries）**：不惩罚"不做"，只庆祝"做了"；中断可恢复，无时间惩罚
5. **自我决定（Self-Determination）**：满足自主感、胜任感、联结感三大基本心理需求
6. **具身认知（Embodied Cognition）**：用身体可感的隐喻（花园、星图、河流）替代抽象概念

### 🌸 花瓣一：晨露·情绪栖息（Mood Sanctuary）

| 子功能 | 描述 | 交互方式 |
|--------|------|----------|
| **情绪签到** | 每次打开用3个emoji记录当下心情 | 点击表情，无需打字 |
| **呼吸花园** | 跟随视觉引导进行4-7-8呼吸法 | 屏幕上的花随呼吸开合 |
| **AI 暖伴** | 非诊断式对话，温暖共鸣+正向重构 | 自然语言，非说教式 |
| **感恩一瞬** | 每天只写一句话——今天发生了什么好事 | 一句话输入框，可跳过 |
| **情绪年轮** | 用树木年轮可视化情绪变化趋势 | 被动查看，不主动推送 |

**心理依据**：情绪标注（Affect Labeling）可降低杏仁核激活；4-7-8呼吸激活副交感神经；感恩练习提升积极情绪基线。

### 🌸 花瓣二：数语·数学花园（Math Garden）

| 子功能 | 描述 | 心理设计 |
|--------|------|----------|
| **概念种子** | 每个数学概念是一颗种子，学懂即开花 | 可视化成长，具身认知 |
| **微探险（3-5min）** | 一个概念=一个小关卡，用故事包裹 | 认知负荷控制在工作记忆容量内 |
| **向量花园** | 线性代数用花园网格可视化向量运算 | 抽象→具象，空间直觉 |
| **微积分河流** | 极限=靠近河岸，导数=水流速度，积分=蓄水池 | 动态隐喻，降低抽象门槛 |
| **无错模式** | 没有"错误"，只有"尝试路径"，展示尝试带来的变化 | 消除评价恐惧 |
| **每日一题** | 每天只推送一道题，答对获得花园装饰 | 微习惯策略，降低启动阻力 |

**心理依据**：隐喻思维（Metaphorical Thinking）降低数学焦虑；微学习（Microlearning）适配焦虑状态下缩短的注意力；成长可视化满足胜任需求。

### 🌸 花瓣三：萤火·代码星火（Code Sparks）

| 子功能 | 描述 | 心理设计 |
|--------|------|----------|
| **积木→文本渐进** | 第一阶段：拖拽积木拼代码 → 第二阶段：积木+文本对照 → 第三阶段：纯文本 | 最近发展区，逐步撤离脚手架 |
| **即时可视反馈** | 每一行代码立即产生可见效果（颜色/动画/图形） | 即时强化，多巴胺微循环 |
| **临摹→改编→创作** | 第一步：复制代码看效果 → 第二步：改一个参数 → 第三步：加自己的改动 | 模仿学习，零失败的创造起点 |
| **碎片项目** | 5-10行代码的小项目：生成一朵花、一个星空、一句诗 | 完成感>复杂度 |
| **好奇心地图** | 从效果出发（"我想做一个星星闪烁的效果"），反推需要的知识 | 目标驱动，避免"学而无用"感 |

**心理依据**：Scratch→Python 渐进降低"编程=难"的刻板印象；即刻可视反馈利用游戏化即时奖励机制；低门槛创作重建自我效能。

### 🌸 花瓣四：星图·方向探索（Path Finder）

| 子功能 | 描述 | 心理设计 |
|--------|------|----------|
| **兴趣卡片** | Tinder式滑动：左滑不感兴趣，右滑感兴趣 | 低认知负荷，游戏化探索 |
| **能力拼图** | 通过迷你游戏评估思维偏好（逻辑/空间/语言/人际等） | 不叫"测试"，叫"拼图" |
| **故事馆** | 不同职业的真实人物用1分钟视频讲"我的一天" | 社会学习，替代性经验 |
| **如果...会怎样** | 交互式情景："如果你学了数据分析，你可能会..." | 未来自我连续性，希望感构建 |
| **方向星轨** | 综合上述数据生成个性化方向建议（非标签化） | 自主感：用户始终可选择"换一条路" |

**心理依据**：可能自我（Possible Selves）理论——通过构建未来自我形象激发行动动机；兴趣探索降低同一性弥散焦虑。

### 🌸 花瓣五：树洞·安全空间（Safe Space）

| 子功能 | 描述 | 心理设计 |
|--------|------|----------|
| **环境音景** | 雨声、篝火、森林、海浪等白噪音 | 降低环境焦虑，营造安全锚点 |
| **引导冥想** | 3/5/10分钟的呼吸与身体扫描冥想 | 正念减压（MBSR简版） |
| **匿名星群** | 轻度匿名社区：用星星昵称，可发情绪状态或鼓励他人 | 社会支持，去身份化的安全感 |
| **成长时间线** | 记录每次微小的进步，形成可视化的"我已走了这么远" | 反刍抑制，积极自传体记忆构建 |
| **急救箱** | 情绪崩溃时的紧急工具包：冰冻感官（握冰块）、5-4-3-2-1接地练习引导 | DBT痛苦耐受技能精简版 |

**心理依据**：DBT/CBT 循证技术精简融入；匿名同伴支持降低社交焦虑；积极自传体记忆对抗抑郁的过度概括化记忆。

## 三、核心技术架构

### 3.1 跨平台策略

```
┌─────────────────────────────────────────────────────┐
│                    SHARED CODEBASE                   │
│              React 18 + TypeScript + Vite            │
├─────────────────────────────────────────────────────┤
│                                                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │   Web    │  │   PWA    │  │  Native (计划)    │  │
│  │ (SEO/SSR)│  │(可安装APP)│  │  Capacitor 封装   │  │
│  └──────────┘  └──────────┘  └──────────────────┘  │

│   Responsive Design (Mobile-First)                  │
│   Tailwind CSS + Framer Motion                      │
└─────────────────────────────────────────────────────┘
```

### 3.2 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| **前端框架** | React 18 + TypeScript | 生态成熟，组件化思维，适合复杂交互 |
| **构建工具** | Vite 5 | 极速HMR，PWA插件生态 |
| **样式** | Tailwind CSS 3 | 原子化CSS，暗色/暖色主题切换便捷 |
| **动画** | Framer Motion | 细腻的微交互动画，物理弹簧动画 |
| **路由** | React Router v6 | SPA路由，支持嵌套布局 |
| **状态管理** | Zustand | 轻量，无样板代码，适合中小型状态 |
| **PWA** | vite-plugin-pwa + Workbox | 离线可用、可安装、推送通知 |
| **AI对话** | OpenAI API / 本地模型 | 温和的非诊断式情感对话 |
| **数据可视化** | Recharts + D3 | 情绪趋势图表，数学概念可视化 |
| **后端** | Node.js + Express + Prisma | RESTful API，可渐进扩展 |
| **数据库** | PostgreSQL + Redis | 关系型主库 + 缓存/会话 |
| **认证** | JWT + OAuth 2.0 | 跨平台统一认证 |
| **部署** | Docker + Nginx | 容器化，易于扩展 |

## 六、非功能需求

| 需求 | 指标 | 策略 |
|------|------|------|
| **可及性** | WCAG 2.1 AA | 高对比度模式，屏幕阅读器兼容，字体可缩放 |
| **离线能力** | PWA离线可用 | Service Worker缓存核心资源 |
| **隐私安全** | 数据加密存储 | 端到端加密，用户数据自主可控 |
| **性能** | FCP < 1.5s, LCP < 2.5s | 代码分割，懒加载，CDN |
| **容错** | 任何操作可撤销/可恢复 | 软删除，时间旅行式回滚 |
| **包容性** | 不设"失败"状态 | 所有路径都是有效路径 |
